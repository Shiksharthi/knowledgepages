Dimension Reference Guide — What each column means, why it matters & how to read the ratings
Consistency
Does every user see the same, latest data at the same time? When you write something, can everyone else read it immediately — or might they briefly see old data? This is the classic trade-off in distributed systems: the more consistent, the slightly slower the writes.
Strong / ACID: Everyone always sees the latest data. No surprises. Best for banking, payments, inventory. Slight write overhead.
External Consistency (Spanner): Even stronger — globally ordered transactions using atomic clocks. Unique to Google Cloud Spanner.
Tunable / Session: You pick your trade-off per query. CosmosDB offers 5 levels. DynamoDB lets you choose per read. Great for flexibility.
Eventual: Briefly stale reads possible (milliseconds–seconds). Fine for CDN caches, social feeds, analytics. Faster & cheaper writes.
Watch out: Eventual consistency in financial or inventory systems = overselling, double-spending bugs. Always match consistency to your use case.
Availability
Is the service always reachable? Measured as an uptime SLA (Service Level Agreement). Even a 0.01% difference in nines = hours of downtime per year. Multi-region and multi-AZ designs push availability higher, but at higher cost.
99.999% — 5 nines: ≈5 min downtime/year. DynamoDB Global Tables, CosmosDB multi-region writes. The gold standard.
99.99% — 4 nines: ≈52 min/year. Most managed cloud services (GCS, GKE, Akamai, S3). Sufficient for most production apps.
99.9% — 3 nines: ≈8.7 hrs/year. Standard SLA for many services. Self-managed systems without HA config often land here.
Self-managed Kubernetes: No SLA — you own it. HA needs careful setup (3+ control plane nodes, etcd backups, multi-AZ nodes).
Latency
How fast does the service respond to a request? Under 100ms feels instant to users. Over 1 second feels slow. Latency is affected by geography (distance to servers), cold starts, number of network hops, caching, and concurrency.
Ultra Low (<1–10ms): DynamoDB, CDN edge serving, ILB, NLB — feels instant even under heavy load. Data is nearby.
Low (10–100ms): AlloyDB, MongoDB, Apigee, Cloud Run (warm), GKE — fast enough for all user-facing workloads.
Medium (100ms–1s): Istio (sidecar overhead per hop), cross-region calls, Pub/Sub delivery. Acceptable for background work.
Cold Starts (1–3s): Lambda, Cloud Run, Azure Functions when idle. Fix: set min instances = 1 or use Provisioned Concurrency.
Archive Retrieval (min–hours): GCS Coldline/Archive, S3 Glacier — cheap storage but not for real-time access. Plan ahead.
Security
How protected is the service from unauthorized access, data breaches, and attacks? Covers: who can access (IAM), how data travels (TLS/mTLS), how data is stored (encryption), network isolation (VPC), and compliance certifications (HIPAA, PCI-DSS, SOC 2).
Very High — Zero Trust: Istio (auto-mTLS between all services), Akamai (WAF + Zero Trust), Walmart WCNP (full data sovereignty — no shared responsibility).
High — Managed Cloud: IAM, encryption at rest+transit, VPC isolation, private endpoints, audit logs, CMEK. Standard for GCP/AWS/Azure managed services.
Medium — DIY Kubernetes: Self-managed K8s is powerful but YOU configure RBAC, network policies, secrets encryption, pod security. Easy to miss steps.
Watch out: "Shared responsibility" — cloud secures the platform; YOU secure your app config, IAM policies, data classification, and code.
Scalability
Can the service handle 10×, 100×, or 1000× more traffic without breaking or needing manual intervention? Two types: Vertical (bigger machine) — has limits. Horizontal (more machines) — near-limitless. The best cloud services scale automatically.
Infinite / Fully Auto: Akamai, CloudFront, S3, DynamoDB, Pub/Sub — absorb any load spike with zero configuration. No pre-warming needed.
Scale-to-Zero: Cloud Run, Lambda, Azure Functions — cost $0 when idle, scale up in seconds. Perfect for variable workloads.
Managed Auto-scale: GKE, AKS, Aurora — autoscalers handle growth; you set limits and policies. Good for stateful workloads.
Manual / Config-Heavy: Self-managed Kubernetes — requires Cluster Autoscaler setup, node group config, capacity planning. Not automatic out-of-box.

Quick Rule of Thumb: For speed to users → CDN (Akamai/CloudFront). For internal traffic → ILB/Service Mesh. For API management → Apigee. For global data → CosmosDB or Spanner. For fast key-value → DynamoDB. For flexible docs → MongoDB. For containers → GKE or AKS. For no-server code → Cloud Run or Lambda. For files → GCS or S3.

Ratings are general guidance — actual performance depends on configuration, region, tier, and workload. Always benchmark for your specific use case.
